# Mux UI in peblish

One page for the lanes that move the app onto Mux UI. How each component is meant to be used, its weight and its gaps are in the catalogue (`/Users/admin/.agents/plans/feddit/lane-notes/mux/catalogue.md`); this page is the contract.

## The import rule

- Mux UI comes only from the vendored tarball, `vendor/muxui/muxui-react-0.1.0-rc.8-c4.tgz` (candidate c4 of rc.8, built from Mux UI's `main`; provenance in `vendor/muxui/README.md`), a dependency of `packages/ui` alone.
- Only `packages/ui` imports `@muxui/react`. Routes and the shell import one module per component: `import { Card } from '@peblish/ui/components/card'` (no extension, no barrel). One module per component keeps tree-shaking working: a route that imports `separator` does not load `sidebar`.
- A wrapper re-exports the component, its parts and its prop types and nothing else. If one you need is missing, add `packages/ui/src/components/<kebab-name>.tsx` the same way and say so in your notes.
- The app's own composed components (`PostCard`, `CommentThread`, `VoteControl`, `ReplyBar`, `Prose`, `Handle`, `Time`, `Badge`, the form fields) keep their public props.
- Icons are Lucide (`lucide-react`, the set Mux UI draws its own with, pinned to the version Mux depends on), and like `@muxui/react` only `packages/ui` imports it (`mux-only-in-ui` in `.dependency-cruiser.cjs`). Everyone else imports from `@peblish/ui/components/icons`, which wraps each glyph by name: 1em square, `currentColor`, `aria-hidden` unless named. Need another glyph? Add one line there. Every `Sidebar.NavItem` takes one through `icon`: without it Mux draws the label's first letter, which becomes part of the link's text.
- Shared composed pieces (built from Mux components and tokens by the GW2 lane, in the same folder): `badge`, `notice`, `link-tabs`, `pager`, `fact-list`, `empty-state`. Use them rather than composing your own; their CSS is linked from `packages/web/src/styles.css`.

## Tokens

Style only with Mux tokens (`var(--muxui-...)`), or the few `--pb-*` aliases below (every other job uses the Mux token itself, listed under the table; role badges are `Badge`), which are themselves only Mux tokens. No hex, rgb or hsl, no hand-written radius, shadow, font family or font size. Layout (grid, flex, widths, gaps) is fine. The app uses Mux UI's own light and dark schemes (`data-muxui-color-scheme` on `<html>`); there is no true black. Appearance is System, Light, Dark; a `scheme=black` cookie stored before that choice was removed still renders as dark (`theme/root.tsx` maps it).

| Token             | Role                            | Mux token                                       |
| ----------------- | ------------------------------- | ----------------------------------------------- |
| `--pb-up`         | up vote                         | `--muxui-component-taggroup-orange-foreground`  |
| `--pb-down`       | down vote                       | `--muxui-component-taggroup-indigo-foreground`  |
| `--pb-warn`       | warning                         | `--muxui-component-taggroup-warning-foreground` |
| `--pb-error`      | danger and error                | `--muxui-semantic-feedback-invalid`             |
| `--pb-ok`         | success                         | `--muxui-component-taggroup-success-foreground` |
| `--pb-page-width` | the page column's width (940px) | none: Mux has no width tokens                   |

The accents use TagGroup's hue foregrounds because they are the only Mux accent colours with a dark branch (catalogue gap G7); each is 6.5:1 or better on the page in both schemes. For a tinted fill behind one, use the same hue's `-tint-weak` (`--muxui-component-taggroup-success-tint-weak`). `--muxui-semantic-status-success` and `-status-warning` fail contrast as text: use them for stripes only. Do not use `--muxui-semantic-action-danger-foreground` for text (no dark branch).

The other jobs, straight from Mux (prefix `--muxui-`): text `semantic-content-default`; muted text (meta lines, counts, times) `semantic-content-muted`; links `semantic-content-link`; separators `semantic-border-subtle`; the comment tree's 2px thread line `semantic-content-faint` (3:1 or more in both schemes; Mux's strong border is 1.57:1 on the light page); hover fill `semantic-surface-hover`; page `semantic-surface-background`; raised surface (cards, menus, the docked bar) `semantic-surface-raised`; quiet fill (notice, code, stub) `semantic-surface-subtle`; link hover `semantic-content-link-hover`; borders on controls and collections `semantic-border-default`; dense row lines `semantic-border-faint`; selected item `semantic-selection-background`; focus ring `outline: 2px solid var(--muxui-semantic-focus-ring)` (Mux's own `:focus-visible` rule already draws it, so the app no longer sets one). Anything else: the catalogue's "Which token for which job" table.

### Brand packs

An instance may have a brand pack (`packages/ui/src/brand/<id>/`, chosen by the site setting `site.brand`; `pack.ts` there describes the folder). Its `pack.css` is the one stylesheet that sets values by hand: Mux reference tokens on `:root` (only those that differ from Mux's default; semantic and dark values follow from them), Mux tokens to tokens (feddit's label weight 500), the wordmark's `--pb-brand-wordmark-font` and `--pb-brand-wordmark-weight`, and the wordmark's `@font-face`. The guard's `css-brand-pack` rule holds it to that. Components never read a pack: they keep using the tokens above, which the pack changes. With no pack, nothing of this loads and the app is Mux UI's default palette.

### Base rules

Mux UI rc.7 components bring their own font and box model: they no longer take font, box sizing or Separator margin from the page, and Mux's base rule gives the body its text face, size (fluid 14 to 16px), line height and colour. What `tokens.css` adds:

- `*, *::before, *::after { box-sizing: border-box }`, in the `reset` layer, for the app's own elements. Mux reverts its own elements to the browser's box model (content-box for most), so an app rule that gives a Mux part a width including its padding (`inline-size: 100%` on a `Card`) also sets `box-sizing: border-box` on it, as `auth.css` does for the auth card.
- `.muxui-avatar__fallback { box-sizing: border-box }`: a Mux UI rc.7 bug, the fallback is 100% wide plus its padding, so without this the initial sits off centre.
- `components/sidebar.css`: `.muxui-sidebar__nav-link` and `.muxui-sidebar__mobile-header` size as `border-box`. Under Mux's content-box a navigation row is 50px (its 36px minimum plus padding) and the phone bar gains its 1px border; the picked layout has 36px rows and a 56px phone bar. Delete it when Mux sizes these parts as border-box itself. (The top bar is HeaderNav's `background` variant, which has no border, so it is 64px as Mux sizes it.)
- `body`: no margin, the page surface (`--muxui-semantic-surface-background`) and `overflow-wrap: anywhere`.
- The app has no `:focus-visible` rule of its own; Mux's applies.
- `.pb-page` padding takes Mux layout tokens.
- Under the system's reduced motion Mux's fields (Input; TextField and SearchField; TextArea; Select's trigger) still ease their edge and glow over 350ms: Mux's own query stills its buttons and links, and only its `data-muxui-motion='reduced'` setting stops a field's clock. `tokens.css` stills them app-wide.

New `--pb-*` tokens go in `packages/ui/src/tokens/tokens.css` (the groundwork lane's file; ask root) and are only Mux tokens. Prefer using the Mux token directly.

### What candidate c1 changed for the app

- Dark scheme only: muted text, field labels (and so Tabs' labels) and links are a half-and-half mix of Mux's steps 70 and 80, lighter than before (muted `rgb(181 177 173)`, links `rgb(144 186 189)` on the page). Light is unchanged.

## Client-only components under server rendering

Andrew's rule (2026-11-11): the app is readable without JavaScript and interactive with it. A menu, drawer or switch may need scripts, and a browser test that asserts one works with scripts off may be rewritten; plain form posts must keep working.

Every page renders on the server and must hydrate without warnings (the e2e hydration marker). Mux overlays (Menu, Dialog, AlertDialog, Popover, Tooltip, Lightbox, the Sidebar and HeaderNav drawers, `Sidebar.AccountMenu`) render nothing in the server HTML and mount on open, so they are safe to render on the server, but their triggers do nothing until hydration (G1). The pattern:

1. Render the trigger on the server as usual. Never branch markup on `typeof window`: that is a hydration mismatch.
2. A form that posts keeps a real `<form method="post">` (sign out included), so it works before hydration even when its trigger sits in a menu that does not.
3. A control that only works with scripts is disabled until hydration with `useHydrated()` from `@peblish/ui/composer/use-hydrated.ts` (false on the server and during hydration, true after; no extra render), as the composer does.
4. Code that is heavy and only needed after an action is split with `React.lazy` and rendered inside `Suspense` only once the action happened (the composer sheet in `web/shell/create-post.tsx`).
5. `ColorModeToggle` writes the scheme to `<html>` and localStorage on every render: do not use it. The scheme control is built from `ToggleButtonGroup` or `Menu` plus `theme/root.tsx`.
6. Avatar shows its fallback until hydration; pending submit Buttons are disabled until hydration. Both are by design.

## State without JavaScript

Mux hides the native input of its choice controls and draws the visible box, tick, dot and thumb from `data-muxui-state-*` attributes that React sets. Since rc.7 Mux's own stylesheet also draws Checkbox, CheckboxField, CheckboxGroup, Switch, SwitchField, RadioGroup and RadioField from the native input while those attributes are stale (scripts off, or before hydration), including the keyboard focus ring and forced colours, so the app adds nothing. `e2e/ui-nojs` is the regression test: the drawing follows clicks and keys with scripts off, matches a hydrated page pixel for pixel in light, dark and forced colours, and Mux's input rules change nothing once hydrated.

## The frame

The shell (`packages/web/src/shell/shell.tsx`) draws the header, the sidebar, the phone's bars and every page's view header; a route renders its `<main>` and may add three things:

- A loading host: `pendingComponent` on the route, from `packages/web/src/shell/pending.tsx` (the feeds, the post page, the directory, a community, a profile and the inbox have one): when the route's data takes longer than the router's pending delay, a busy `<main>` holds the screen's skeleton and one status saying what is loading. A route with its own view header draws that header in its host too, from what it knows before its data and with the app's own styles only (the route's stylesheet comes with the page), and the shell leaves its default bar out while it loads.
- A right rail: `Rail` from `packages/web/src/shell/rail.tsx` (an `aside` with a name) after its `<main>`, as a sibling (`<><main>…</main><Rail label={…}>…</Rail></>`). The frame puts it beside the 40rem centre at 19.5rem, sticky under the header, stands its panels `layout-action-gap` apart (`className` is the page's own, for what it styles inside them), and drops it where the page is narrower than 62rem, before the phone layout below 860 px.
- Its own view header: `staticData: { viewHeader: 'own' }` on the route, and `ViewHeader` from `packages/web/src/shell/view-header.tsx` at the top of its `<main>` (inside a `.pb-page` it runs the column's width from its top) with its `title`, `phoneTitle` (what a phone's bar shows in the title's place) and `trailing` actions (`root` for a top destination, which has no Back). A page whose h1 is in the page passes `quiet={useHeadingInView(pathname)}` and its name as the title, as the inbox does. Otherwise the shell's bar shows the page's name from its title once the page's h1 has scrolled under it. Either way the bar is a navigation named Page, with Back once the tab can go back, and on a phone the mark (or the site's name, at most 40% of the window), the finder and the drawer's button.
- A wide centre: `staticData: { centre: 'wide' }` for a page whose staff table (52rem, in an outlined card) must sit whole on a computer (the queue, Bans, Peers, Media, Registration, the site pages list). Beside it the rail gives way below 76rem.

On a phone (below 860 px) Mux's small and medium control sizes and its button minimum are the frame's 44px `--pb-touch`, on every page and in every portal (Mux's control sizes stop at 40); an avatar keeps Mux's sizes. The bottom bar's fifth destination is the You page (`/you`); the viewer's profile is a page under it, with Back. A web stylesheet may read the frame's custom properties (`--pb-touch`, `--pb-dock-end`); the guard allows it for `packages/web` only.

The sidebar (`packages/web/src/shell/sidebar.tsx`) is Mux's Sidebar as c3 has it: `NavList`'s `navLabel` is its landmark ("Feeds and communities"); in the column its sections fold (`collapsible`, remembered in this browser and drawn open by the server), and folded into the rail the site's pages are one menu in `Sidebar.Footer`; the phone drawer's sections do not fold. Pinned communities (a later branch) go first in Communities with a `Sidebar.NavDivider` after them, and a row's own control is `NavItem`'s `action`; `/kit/sidebar` lays both out. Under the system's reduced motion a row still eases its colours, so `components/sidebar.css` stills them. Still Mux gaps: Menu has no checked item (Appearance keeps its own tick and a hidden "current"), and Link has no `aria-current="true"` (the bottom bar marks a section with `"page"`).

A bar a page docks at the window's foot sticks at `inset-block-end: var(--pb-dock-end)`, a web stylesheet's token (`shell.css`), so on a phone it sits above the bottom bar; `shell.css` does this for the thread's reply bar (`.pb-reply`). The root's scroll padding keeps focus and in-page jumps clear of the sticky bands.

## State pages

Each composition can have a page of its states in the component gallery, `/kit/<key>` (like `/kit`, only with `PEBLISH_UI_KIT=1`): add it to `compositions` in `packages/web/src/routes/kit/-states.tsx`, one sample per state it takes as a prop (rest, selected, disabled, pending, invalid, in the state matrix's order; selected stands for current, checked and expanded). `galleryStates` in `e2e/support/states.ts` hovers, focuses from the keyboard and presses the rest sample, and for every state, in light and dark, under forced colours, under reduced motion and at a phone's width, runs axe and measures text, icon and focus ring contrast, leftover motion and target size; `stateProblems` lists what fails. A field without a focus ring is held to its edge, which Mux's fields draw in the focus colour; an edge counts every side that paints a border; a single-choice ToggleButtonGroup's chosen fill (a layer beside the buttons, under their label copies) is seen; and at a phone's width a form's fields and buttons are held to 44px whatever floor a composition allows its other targets. `e2e/ui-states/states.spec.ts` runs it on Button and VoteControl.

## Examples

A Card with actions (a community in a list):

```tsx
import { Button } from '@peblish/ui/components/button';
import { Card } from '@peblish/ui/components/card';
import { Link } from '@peblish/ui/components/link';
import { Text } from '@peblish/ui/components/text';

<Card.Root variant="outlined" padding="sm">
  <Card.Header>
    <Text as="h2" variant="title" size="sm">
      <Link href="/c/news">news</Link>
    </Text>
  </Card.Header>
  <Card.Body>
    <Text color="muted">{members}</Text>
  </Card.Body>
  <Card.Footer>
    <Button variant="primary" onActivate={join}>
      {labels.join}
    </Button>
  </Card.Footer>
</Card.Root>;
```

Tabs with a Table (admin). Tabs are buttons, not links (G4): keep `value` in the route and navigate in `onChange`.

```tsx
import { Table } from '@peblish/ui/components/table';
import { Tabs } from '@peblish/ui/components/tabs';

const reports = (
  <Table
    aria-label={labels.reports}
    columns={[
      { id: 'post', label: labels.post, isRowHeader: true },
      { id: 'reason', label: labels.reason },
    ]}
    rows={items.map((report) => ({
      id: report.id,
      values: { post: <Link href={report.href}>{report.title}</Link>, reason: report.reason },
    }))}
  />
);

<Tabs
  aria-label={labels.admin}
  value={tab}
  onChange={go}
  keyboardActivation="manual"
  items={[
    { id: 'reports', label: labels.reports, panel: reports },
    { id: 'bans', label: labels.bans, panel: bans },
  ]}
/>;
```

A Sidebar item. Pass the same navigation to the column and the phone drawer and mark `current` in both.

```tsx
import { HouseIcon } from '@peblish/ui/components/icons';
import { Sidebar } from '@peblish/ui/components/sidebar';

<nav aria-label={labels.communities}>
  <Sidebar.NavList>
    <Sidebar.NavItem href="/" icon={HouseIcon} current={path === '/'}>
      {labels.home}
    </Sidebar.NavItem>
    <Sidebar.Section label={labels.subscribed}>
      <Sidebar.NavItem href="/c/news">news</Sidebar.NavItem>
    </Sidebar.Section>
  </Sidebar.NavList>
</nav>;
```

The three examples type-checked against rc.6; rc.7 removes no export or prop they use.
