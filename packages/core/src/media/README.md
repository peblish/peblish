## Cleaning, and what it does not do

`cleanImage` parses the container strictly and writes it again from the parts that decide what is drawn. Exif (GPS, camera, owner), XMP, IPTC, ICC profiles, comments, PNG text and time chunks, GIF comment and XMP extensions, WebP `EXIF`, `XMP ` and `ICCP` chunks and any bytes after the image are gone. A JPEG keeps one 34-byte Exif segment with only its orientation (phone photos would display sideways without it). A damaged file is refused (`media.invalid_image`), and so is anything past 8192 pixels a side or 40 million pixels (`media.too_large`).

Every kept structure must be exactly as long as its fields define, so no marker rides in the tail of a table, a header, an `IEND` payload, a loop-count block or a `VP8X` chunk; a palette image's `tRNS` holds at most one alpha byte per `PLTE` entry, and a PNG chunk that is allowed once (`PLTE`, `tRNS`, `acTL`, `sRGB`, `gAMA`, `cHRM`) is kept once, a repeat dropped as decoders ignore it; a JPEG's Adobe `APP14` segment is the one place real files carry extra private bytes, and it is written again at its 12 defined bytes. A JPEG may hold at most 16 quantisation tables, 256 Huffman tables, 64 arithmetic-coding pairs and 16 restart-interval segments (`MAX_ENTRIES`; cameras write 2 to 4 of each, so only a stress file of a thousand scans exceeds them), each with a table id from 0 to 3, which bounds what the opaque table values can carry. Every animation frame (a GIF frame, an APNG `fcTL`, a WebP `ANMF`) must be non-empty, inside the canvas and, for WebP, carry one raster chunk of its own size. The pixels are neither decoded nor re-encoded: no native or wasm codec ships in the image, and nothing allocates per pixel, so there is no decompression bomb to defend against. The price is that an upload is the image as sent, not a resized copy, and that the compressed bitstreams themselves (JPEG scan data, `IDAT`, GIF LZW data, `VP8`, `VP8L` and `ALPH` payloads) stay opaque: bytes hidden inside them are not found without decoding the pixels, lane SAFE's scan is the second line.

Limits apply to uploads only: 8192 pixels a side and 40 million pixels in all, checked on the cleaned canvas. A proxied remote image is **not** dimension-limited, only size-limited (10 MiB, and it must be a raster type by its first bytes): the proxy never decodes it and the viewer's browser decides what to do with a huge canvas.

## Link previews and their budget

`fetchLinkPreview` makes the server fetch an address a person chose, but it does not count attempts itself. The composer's server function calls `attempt('link-preview', { ip, id })` (`identity/throttle.ts`: 30 a client address and 20 an account in ten minutes) first, and only then `fetchLinkPreview`; a caller that skips the throttle gets no protection from this module. What comes back is safe to hand to `createPost`: a thumbnail URL over 2,000 characters or a content type that is not a media type is returned as null, judged by `NewPost`'s own validators.

## Rows and serving

Every stored row (an upload; a link preview stores nothing) is `scan_state = 'pending'` and nothing serves it. Lane SAFE consumes `media.stored`, scans the object at `media.storage_key` (`media/<id>.<jpg|png|webp|gif>`) and sets the state; its route `/media/<id>` serves clean rows only, with the stored `mime_type`, `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; sandbox`. A link preview's `thumbnailUrl` is the page's `og:image` URL, stored as the post's `thumbnail_url` as it is; pages show it through the proxy below, so no copy of a remote picture exists until SAFE's scanning is live.

## The remote-media proxy (decision 5)

Remote images reach viewers only as `/media/proxy/<signature>/<target>`: `target` is a reference in base64url (the content the image is shown for, then the remote URL), `signature` an HMAC-SHA-256 of it under `derivedKey('media-proxy')` (a key derived from `BETTER_AUTH_SECRET`, `identity/auth.ts`). The content is a post, a comment or an actor (a profile or a community page); on every request the route asks `contentShown` (`reference.ts`) whether it is still shown to the viewer making it, so an image stops loading, saved URL included, once its content is removed, deleted or gated for that viewer, with no list of revoked URLs. Text that belongs to no content (a draft's preview, a site page) gets a reference that expires at the end of the hour after the one it was made in. The route answers 404 to anything unsigned, altered or expired, to withheld content and while `remote_media.enabled` is off. Otherwise it fetches through `safeFetch` (http or https, 3 redirects, 15 s, 10 MiB, nothing from the viewer sent upstream), accepts JPEG, PNG, GIF, WebP and AVIF by their first bytes (SVG, HTML and the rest are 415, an oversize body is 413, a private address is 403, any other upstream trouble 502 or 504), and answers with the type it sniffed, `Cache-Control: private, max-age=600` (browsers only; no edge cache holds remote media for the beta), `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; sandbox`. Nothing is written to the database, the bucket or the disk. Capacity: at most 32 upstream fetches run at once in a process and 64 more wait their turn (`proxyLimits`, `slots.ts`); past that the route answers 503 with `Retry-After: 2`. A request whose client gives up while it waits for a turn leaves the queue (the route passes `request.signal`); a fetch already running is not cancelled and ends within its 15 s. Each fetch holds up to 10 MiB in memory, so 32 of them are 320 MiB at the very worst. A limiter per client address is a later item (it needs a throttle scope in lane A's `identity/throttle.ts`, and the signed URLs are public, so the bound is what protects the server for now). `siteMarkdown()` sets `proxy` to the builder, so Markdown images and remote HTML go through it; for a post's `thumbnailUrl` or an image post's `url`, call `createMarkdownRenderer().image(url, content)` (and pass `content` to `render` and `sanitize` for a body), which returns a root-relative path on this instance (one slash, then not a slash or a backslash: `https://<origin>//evil.example/x.png` is not one and goes the proxy way), the proxy path for a remote one, or `null`.
