# Markdown and remote HTML

Two entry points, one allowlist:

- `renderMarkdown(source, options)` (`render.ts`) renders a post or comment body. It returns sanitised HTML, a plain-text excerpt (no spoiler bodies, no footnotes), the mentions and the links found, and whether the source was cut at `maxLength`.
- `sanitizeRemoteHtml(html, options)` (`sanitize.ts`) cleans the HTML `content` of a remote object from Lemmy, PieFed, Mbin or Mastodon. It returns the same fields, without mentions.

Both paths end in the same sanitiser, so the hooks (`rewriteImageUrl`, the image policy) and the guarantees are the same for both. Options and results are ArkType types in `@peblish/schema/markdown`. The web app calls both through `packages/web/src/server/markdown.ts`. That wrapper applies the instance origin and the remote-media policy, and memoises per request.

Compared with peers: Lemmy 0.19.21 (the server, which renders the `content` it federates, and lemmy-ui, which renders `source` in the browser) and PieFed 1.8.11. The evidence is in `__fixtures__/peers.json`: what both lab peers federated for each case, made by `__fixtures__/capture.ts`, plus the peer pairs from the Phase 0 spike captures. `equivalence.test.ts` asserts every row below and names every difference.

## Sanitiser allowlist

Elements: `p br hr h1-h6 strong b em i u s del ins sub sup code pre kbd blockquote ul ol li table thead tbody tfoot tr th td details summary img a span div section ruby rt rp`. `strike` becomes `s`, PieFed's `tg-spoiler` becomes `span.spoiler`, and the text of either stays out of the excerpt. Any other element is unwrapped: the tag goes and the text stays. A few elements are dropped with their whole content: `script style template textarea title iframe object applet noscript noembed noframes xmp plaintext svg math select datalist head audio video canvas frameset`.

Attributes, and nothing else:

- `a`: `href`, `title`, `id` (footnote anchors only), `class` (`u-url mention hashtag community footnote-backref`). Every link with a URL gets `rel="noopener noreferrer nofollow ugc"`, and `target` is never kept. A link whose URL is refused is unwrapped.
- `img`: `src`, `alt`, `title`, `width` and `height` (pixels up to 9999 or a percentage up to 100), `align` (left, right, center), `class` (`emoji`), plus `loading="lazy"`.
- `ol`: `start` (digits). `th`, `td`: `align`, taken from `align` or from a `text-align` inline style. `code`: `class` (`language-*`). `span`: `class` (`hljs-*` and its `*_` scope classes, `h-card`, `invisible`, `ellipsis`, `spoiler`). Footnote classes and ids go on `sup`, `li`, `ol`, `hr` and `section`.
- No `style` attribute, no event handler, no `id` except `fn…` and `fnref…` footnote ids, no `name`.

URLs: `http`, `https` and `mailto` (`http` and `https` for images) are checked as the browser's URL parser reads them. Tabs, newlines and control characters cannot hide a scheme. URLs with credentials are refused, and so is every other scheme, `data:` included. A protocol-relative URL (`//host`) and any URL with a backslash (which the URL parser reads as a slash, so `\\host`, `/\host` and `https:\\host` name a host) are refused before resolution, even when they name the base's own host. Any other relative URL resolves against the base (`baseOrigin`, or the remote object's `baseUrl`) and must stay on its origin. Without a base, relative URLs are dropped. Same-page fragments (`#fn1`) stay. URLs are written out in their canonical form. An image URL then goes through `rewriteImageUrl`, which returns where the image loads from (the media proxy, or the URL itself for this instance's media), or `null` to show the image as a link.

Caps: elements nested deeper than `maxDepth` (32) are unwrapped, counting the `tbody` and `tr` a browser inserts in a table, and an image at the cap shows only its alt text; remote input over `maxLength` (500,000 characters) is cut before a partial tag and flagged `truncated`. The sanitiser runs htmlparser2's Tokenizer with its own element stack, because htmlparser2's Parser is quadratic in nesting depth. Every step is amortised constant time, so the time is linear in the input (`perf.test.ts`).

What the output promises: only the allowlist, with every element closed, every attribute checked and escaped and all text escaped, so a browser reads exactly the tags written and a second pass returns the output unchanged. Implied end tags (a block closing a `p`, a list item or cell closing the one before) are applied at the innermost written element, passing over unwrapped ones. The element stack does not model the whole HTML tree builder, so a browser may still rearrange the tags, for example by inserting a `tbody`, moving text out of a table or closing a `p` around a block inside an inline element. All it can rearrange are allowlisted elements with checked attributes.
