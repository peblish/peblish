## 4. Decisions and deviations

1. `mod.ban` already had `communityId: Uuid.or('null')` (`s/events/moderation.ts`); there was nothing to widen. FED-C's site-ban Block can consume it as is.
2. Deviation: the slot props live in one root-owned file, `w/routes/-actions/props.ts`, instead of a `props.ts` per surface (E1 asked for `w/routes/u/-ui/actions/props.ts`). One file keeps the shared `SlotViewer` in one place.
3. Slot props, MODF's contract as the base (decisions): `ContentActionProps = { target: ContentRef; author: ActorRef; community: ActorRef; removed; deleted; viewer: SlotViewer; back }` for the post and comment slots; `ProfileActionProps = { person; viewer; moderatedCommunities; back }`; `CommunityActionProps = { community; viewer; back }`; `SlotViewer = { actorId; moderator; admin }`. COMM's `viewer: {...} | null` and `moderator: boolean` became the shared `SlotViewer` and pages render slots only for a signed-in viewer. E1's block slot gets the author or person from these props, not a bare `target: ActorRef`. MODF's `ProfileModerate` gets `moderatedCommunities` from E1's `readProfile` instead of loading it.
4. Slots render for any signed-in viewer, unless the post gate withholds the post (`withheld !== 'gate'`); removed and deleted content still gets them (a moderator restores). Each slot decides whether it shows anything: report and block hide themselves on the viewer's own content, moderate shows only with `viewer.moderator` or `viewer.admin`.
5. The post page keeps the moderator's "Removed. Only moderators see this post" hint (a notice, not an action). Removed strings: `posts` `action.remove`, `action.removeReason`, `action.removeSubmit`, `action.unremove`, `action.mod`; the `.post-mod` styles.
6. REP's `ReportAction` stub at `w/routes/report/-ui/report-action.tsx` was not created: decisions put the slots at `<surface>/-ui/actions/report.tsx`, and REP may write one shared component under `w/routes/report/-ui/` and re-export it.
7. `ShellData` gains `siteName`, `unread` and `reportCount`. `openReportCount` runs only for a viewer who moderates something or is an admin; anyone else gets `reportCount: null` and no queue link. The badges print the count up to 99, then `99+`. The site name falls back to the host of `PUBLIC_ORIGIN`.
8. `pageTitle(locale, site, name?)` and `titleForRoute(locale, site, routeId)` take the site name; a route's `head` reads it with `rootTitleData(rootLoaderData, fallbackLocale)` (`w/shell/title.ts`).
9. The Admin account menu entry goes to `/admin/settings`, which answers 404 until ADM lands it. Invites stays in the menu, as the mock has it.
10. The admin layout chooses tabs only: admins (role admin with two-factor) see seven, a moderator who is not an admin sees Reports (`ShellData.reportCount !== null`), anyone else none. It admits nobody: each page checks access itself, as `/admin/registration` does, so REP's queue must let moderators in and ADM, MODF and SAFE pages must refuse them.
11. The Settings link on the registration page sits in its status line ("Registration settings"), beside the cap.
12. The `blocked` note replaces the text only for a comment that is not removed or deleted; vote and reply go, the author line, share and the slots stay.
13. `renderActions` is called for every comment, tombstones and blocked ones included, so a moderator can restore.
14. ADM request 5 (default rows) was not in the groundwork item list; done anyway in `ensureSettingRows` (root-owned `db/**`), run by `migrate` before the local instance. It writes every kill switch and `registration.cap`, so ADM's locked readers always find a row.
15. The `posting.enabled` check sits right after `emailUnverified` in both policies, so ADM's `kill-switches.test.ts` can turn its `test.todo` for posting into a test.
16. The `remote_nsfw.accepted` read in the inbox runs on the storing transaction (`t.db`), plain (no lock); the remote fetch reads it with the read pool.
17. Poison skip: the threshold uses the database clock. The batch that skips stops right after the skipped event, so the skip commits on its own even if a later event in the same batch fails. The last failure time is the cursor's `updated_at` (only failures write the cursor while one event keeps failing); `outbox_skipped` keeps consumer, event id, type, last error, failure count, first and last failure, and skip time, keyed by consumer and event.
18. Deviation, minor: `s/{refusals,events}/directory.ts` exist although DISC's brief says it adds none; the groundwork brief lists them. DISC may leave them empty.
19. `e2e/support/site-name.ts` reads the brand; the title specs expect `<page> · <brand>`, so they pass whether or not a lane database holds a `site.name`.
