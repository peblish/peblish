## 4. Decisions and deviations

1. **Deviation: images are cleaned, not re-encoded.** `cleanImage` parses JPEG, PNG, WebP and GIF containers strictly and writes them again from the allowlisted parts; the pixel data is not decoded. The brief asks for a re-encode, and its test (a JPEG with GPS Exif, read back) holds. I chose this over sharp (native; the runtime image has no `node_modules`, and the Nitro and worker bundles would need external handling plus an extended `image-smoke.sh`) and over wasm codecs or pure-JS decoders (no pure-JS WebP decoder, per-pixel memory for a hostile 8192x8192 file). Trade-offs: no resize (a thumbnail is the image as sent; previews cap the download at 2 MiB), AVIF is not an accepted upload or thumbnail type, ICC profiles are dropped (wide-gamut photos may look flatter), and a browser decoder still sees the sender's pixel data (lane SAFE's scanning covers that). Phone photos keep their orientation through a synthetic 34-byte Exif segment. If Andrew wants a true re-encode later, `cleanImage` is the one place to swap, and sharp needs the Dockerfile, the Nitro externals and `image-smoke.sh` to change (all root's).
2. **Deviation: IPv4-compatible `::/96` is refused whole**, not judged by the IPv4 inside (the brief says to check the embedded address). The spike's tests assert `::8.8.8.8` is blocked, the form is deprecated and never a destination. IPv4-mapped and NAT64 `64:ff9b::/96` do check the embedded IPv4 (DNS64 on an IPv6-only host answers real IPv4 peers in the NAT64 block).
3. **Addition: a global-unicast backstop.** IPv6 outside `2000::/3` is refused, so unallocated space and ranges the table does not name are never public. Also named: `3fff::/20` (RFC 9637). An IPv6 zone (`fe80::1%eth0`) and non-canonical IPv4 (`127.1`, `0x7f.0.0.1`) are "not an address", so not public. No `net.BlockList` (its mapped-address behaviour caused the spike's defect).
4. **Additions to the contract** (all additive; the brief's signatures are unchanged): `SafeResponse.truncated?: true`, set when the body was cut at `maxBytes` (delivery wants the status of a chatty 500, the proxy wants to refuse a cut image); `FetchTimeoutError` (transient; every other error besides `BlockedDestinationError` is too); `createSafeFetch(deps)` for tests only (see 5). A malformed URL, a URL with credentials, a scheme the caller did not list and a refused address are all `BlockedDestinationError`. Callers' headers pass through except `Cookie`, `Cookie2`, `Referer`, `Origin`, `Authorization`, `Proxy-Authorization`, `Forwarded`, `X-Forwarded-*`, `X-Real-IP`, `True-Client-IP`, `CF-Connecting-IP`, `Via`, `Host`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Upgrade`, `TE`, `Trailer`, `Expect`; `Accept-Encoding: identity` is the default; Host comes from the URL. On a redirect, `Signature` and `Digest` are dropped, and a 301, 302 or 303 turns POST into GET without the body. With `maxRedirects` used up, the 3xx is returned as it is.
5. **No bypass, and a test that proves it.** Tests that need a stub server on loopback call `createSafeFetch({ resolve, isPublic })`; `fetch.test.ts` fails if any non-test source under `packages/*/src` imports it. Lane LAB and FED-A tests may import it (test files only).
6. **S3 client: `aws4fetch` 1.0.20**, not the AWS SDK: SigV4 signing in a few KB, path-style addressing (`endpoint/bucket/key`) which MinIO and R2 both take. The adapter does not go through `safeFetch`: its endpoint is operator configuration, not a person's URL. Keys are validated (`[A-Za-z0-9._-]` segments, no dot segments). The MinIO tests skip without `S3_ENDPOINT` because CI has no object store (request 1).
7. **Authorization.** Two actions: `media.upload` (needs `uploads.enabled`) and `media.thumbnail` (needs `remote_media.enabled`, which is also why a switched-off site fetches no previews). Both need a local principal and a verified email (`auth.email_unverified`, read FOR SHARE through `actors.user_id`, as posting does) and read the setting FOR SHARE under lock; both mutations set `recheck: true` so a switch flipped between `authorize()` and the write is honoured. Subject is `{}`; the owner is the acting actor. New refusals: `media.unsupported_type`, `media.invalid_image`, `media.too_large`. New event `media.stored { mediaId, ownerId, kind: 'upload' | 'thumbnail' }`.
8. **Order of work in an upload.** authorize, size, clean, `put` to the bucket, then the mutation (no network inside a transaction). If the mutation is refused or throws, the object is deleted again. A crash between the put and the commit leaves an orphan object with no row (risk 4).
9. **Deviation: `fetchLinkPreview(principal, url, options?)`**, not `(url)`: the thumbnail row needs an owner and a grant. It returns `Result<LinkPreview>` (`{ ok: true, title, description, urlContentType, thumbnailUrl, mediaId }` or `{ ok: false, reason }` with `site.disabled`, `auth.required` or `auth.email_unverified`, before anything is fetched). A page that cannot be fetched, a blocked destination or a picture that cannot be used leaves fields null and still returns `ok`. A link straight to an image reports its type and stores nothing. Limits: page 512 KiB, image 2 MiB, 3 redirects, 5 s each. The title is cut at 200 characters (the post title limit), the description at 500.
10. **Tension to confirm: previews store a copy.** The brief (item 5) says the preview image is stored as a `thumbnail` row, so it is. The instruction "nothing fetched from remote servers is stored" is satisfied for the proxy and for federated media (nothing is mirrored), but not for the author's own link-preview thumbnail. If Andrew wants no stored copy at all, the alternative is one change in `preview.ts`: return the `og:image` URL and let `createMarkdownRenderer().image()` proxy it. That would also fix the next point.
11. **A preview's `thumbnailUrl` is `<origin>/media/<id>`, which answers 404 until lane SAFE adds its route** (nothing serves a `pending` row, and the brief says wave 2 serves no stored media). So in wave 2 link posts have the field set and the feed shows no thumbnail. The returned URL is the future serving URL, not a placeholder.
12. **Proxy.** Path `/media/proxy/<signature>/<target>`; `target` is the remote URL in base64url, `signature` its HMAC-SHA-256 under `derivedKey('media-proxy')` from `identity/auth.ts` (lane A's helper, an HMAC-SHA-256 of a fixed label keyed by `BETTER_AUTH_SECRET`; reused as asked, so it is HMAC-based and not a literal HKDF). Unsigned, altered, foreign or switched-off: 404, `no-store`. Otherwise `safeFetch` (http or https: old posts have http images; 3 redirects, 15 s, 10 MiB), only JPEG, PNG, GIF, WebP and AVIF by their first bytes (the remote's `Content-Type` is ignored and the answer carries the sniffed type); 415 for SVG, HTML and the rest, 413 for an oversize image (never cut), 403 for a blocked address, 502 or 504 for upstream trouble. Success headers: `Cache-Control: public, max-age=600`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`, `Referrer-Policy: no-referrer`; no redirect to the remote host. **Root to confirm the figure: 600 seconds, and `public`** (which lets Cloudflare cache it for those ten minutes; `private` would restrict it to browsers). Nothing is written anywhere; the body is held in memory for one response, copied once for the `Response`.
13. **`markdown.ts`:** `siteMarkdown()` now sets `proxy`; `rewriteImageUrl` is `imageSource()` from core (one policy for Markdown images, remote HTML and thumbnails); `MarkdownRenderer` gained `image(url)` (not in the brief, which allowed only the two changes) so pages call one object for a post's `thumbnailUrl` and an image post's `url`. **Not done:** "treat this instance's own media host as own media". No media host exists: stored media is served from the instance origin (SAFE's `/media/<id>`), which the origin check already treats as own. If media moves to another host, add it to `SiteMarkdown` and `imageSource` then.
14. **Consequence of the shared derivation:** `siteMarkdown()` goes through `auth()`, so a page that renders Markdown needs `BETTER_AUTH_SECRET` on a real host, as sign-in already does. Rotating the secret changes the proxy URLs in newly rendered pages and nothing stored (the stored HTML never contains them).
15. **e2e.** `e2e/media/proxy.spec.ts`: unsigned and altered URLs are 404; a signed URL to the stub's loopback address is 403 and the stub sees nothing; the kill switch gives 404; and the post page spec (skips while `/post/<id>` answers 404, so it activates when B1 merges). A positive proxy fetch cannot run in e2e: the server refuses every private address and the sandbox has no public host, so the success path (headers, sniffed type) is covered by `-handler.test.ts` and `proxy.test.ts`.
16. **Strings:** `i18n/media.json` has the three media refusals plus "uploads off" and "previews off" messages in en and de. COMPOSER owns the rest of the composer copy.

## 9. Left open and risks

1. Pixel data is not re-encoded or resized (decision 1); thumbnails are stored as sent (up to 2 MiB) and served only after SAFE.
2. The proxy keeps no server cache and has no concurrency or per-address limit. A signed URL is public in the page HTML, so anyone can make the server fetch it repeatedly (bandwidth equal to the image, no amplification beyond that). A Cloudflare cache rule absorbs most of it; a limiter needs a throttle scope (lane A's file). HEAD is not handled. The whole image is buffered (10 MiB cap).
3. Link previews expose this server's address to the linked site (unavoidable) and rely on the request 4 budget against abuse. The user agent names the instance origin.
4. A crash between the bucket put and the row commit leaves an orphan object (decision 8). No quota on uploads or previews per account.
5. `isPublicAddress` needs a review against the IANA special-purpose registries now and then; a new allocation outside `2000::/3` is refused until the code is updated.
6. Charset handling for previews is the header, then `<meta charset>` in the first kilobyte, then UTF-8; `http-equiv` forms and BOM sniffing are not handled.
7. `safeFetch` does not cancel a DNS lookup that outlives the deadline (it stops waiting for it), and there is no HTTPS stub test (no CA to trust in tests): TLS verification uses the original host name through Node's standard path.
8. The S3 tests skip in CI until request 1; the post-page e2e skips until B1's page exists.
