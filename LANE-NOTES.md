## 4. Decisions and deviations

1. A1, block removal: rechecked too (contract 1, "every person-authorised write"), without the pre-lock, since it does not update the actor row. A site-banned person can therefore not lift a block either.
2. A1: the consumer's `notification.create` and `notification.purge` run as the `scheduled` system principal and stay without recheck.
3. A1, web: the refusal reaches the pages as `?error=auth.site_banned`, which the profile edit form, the inbox, the NSFW gate and the blocks page show as their generic error. A specific line needs `.tsx` edits outside this write set (section 5).
4. W7: a hidden comment is left out of the list (filtered in SQL, so paging stays exact) rather than shown without text: a comment has no cover the way a post card has. Posts on the profile keep their feed behaviour (shown with the card's cover). The profile's counts stay unfiltered, as before (E1 decision 8).
5. S13: the gated retry answers `{ ok: true }` back to the page, which already renders the under-16 state from the cookie, and sets no new cookie, so a retry does not extend the 24 hours.
6. S9: `view.author` on a profile comment was already built from a narrow select; the loader leaves it as it is.
7. S14: the admin page copy ("These placeholders still need a value", "Fill the operator details in Settings, or write the text over") already fits a token that came from an operator detail; no copy change.
8. Deviation (process): `pnpm check` ran twice over batches (A1 with S9; then the other seven), not before each commit. Each commit's own test file was run at that commit's state. The A9 commit carries the old S14 test, which still holds there.

## 8. For later lanes

- A person's write that updates their own actor row (or locks it FOR NO KEY UPDATE later in the body) needs an outer mutation that locks the row first and an inner `recheck: true` mutation run with `.within`: see `updateProfile`, `addBlock`, `deleteAccount`.
- `inboxVisible(viewerId)` (`c/notifications/visible.ts`) is the inbox's visibility rule; any new count or list over `notifications` uses it.
- `publicActorRef` (`c/profiles/read.ts`) is the allowlisted `ActorRef`; use it wherever a row wider than `ActorRef` becomes one.
- `readActivity(..., { nsfw })` takes the browser's `NsfwChoice`; without it, Hide NSFW is on.

## 9. Left open and risks

- The A9 test relies on heap order (it asserts its precondition by `ctid`) and on turning index scans off in its transaction; if a future Postgres changes how `FOR SHARE` meets a sort, the precondition assertion still holds but the test would need a look.
- `c/authz/moderators-cache.test.ts` is timing-sensitive under other lanes' long transactions (not touched here).
